0.1要解决的那个小问题

sandbox/words.txt 里存着一小段英文。你要的输出只有一行：

期望输出
词频： {'agent': 3, 'tool': 2, 'model': 1}

这行的意思：agent 出现 3 次，tool 2 次，model 1 次。字典的键是词，值是个数。

0.2字典怎么“记数”

你需要的动作只有一个：见到一个词，就把它的计数加一。问题是第一次见到的词，字典里还没有它。

counts.get(word, 0) 解决这件事：键存在就返回当前值，不存在就返回 0。

当前字典执行之后
{}counts.get("agent", 0) + 1得到 1，写回 {"agent": 1}
{"agent": 1}同上得到 2，写回 {"agent": 2}

0.3完整程序

word_counts.py
import sys                                      # 读命令行参数、设置退出码
from pathlib import Path                        # 处理路径

DEFAULT_FILE = Path(__file__).parent / "sandbox" / "words.txt"  # 没给路径时读这个文件


def count_words(text):                          # 给一段文字，交回每个词的次数
    counts = {}                                 # 词是键，次数是值
    for word in text.lower().split():           # 统一小写，再按空白切词
        counts[word] = counts.get(word, 0) + 1  # 没见过的词按 0 算，再加一
    return counts                               # 交回整张词频表


def main():                                     # 程序入口
    file_path = Path(sys.argv[1]) if len(sys.argv) > 1 else DEFAULT_FILE  # 有参数就用参数，否则用默认文件
    if not file_path.exists():                  # 文件不存在
        print("找不到文件：", file_path)         # 如实告诉用户
        sys.exit(1)                             # 非零退出码 = 失败
    text = file_path.read_text(encoding="utf-8")  # 一次读完整份文件
    print("词频：", count_words(text))           # 打印结果


if __name__ == "__main__":                      # 只有直接运行这个文件才执行
    main()                                      # 调用入口

1.1哈希表：用空间换时间 A

给一串数字和一个目标值，找出两个数加起来等于目标。最笨的办法是每个数都和后面所有数试一遍，n 个数要试 n² 次。哈希表的做法是：一边走，一边记下“还差多少”。

hash_tables.py
def two_sum(numbers, target):                   # 输入一串数字、目标和
    seen = {}                                   # 值 → 下标
    for index, number in enumerate(numbers):     # 同时拿到下标和值
        need = target - number                  # 还差多少
        if need in seen:                        # 之前见过这个“差”
            return seen[need], index            # 找到配对，交回两个下标
        seen[number] = index                    # 记下当前值和下标
    return None                                 # 走完没配对，返回 None

拿 [2, 7, 11, 15]、目标 9 走一遍：

indexnumberneedseen（处理完这一轮）动作
027{2:0}7 没出现过，记下 2
172{2:0, 7:1}2 出现过，返回 (0, 1)
真实踩过的坑。漏掉 seen[number] = index 这一行，函数永远找不到配对，测试在第六行报 AssertionError。原因是“只查不记”：每一轮都在查，但字典一直是空的。

这行代码的位置也讲究：先查 need，再记 number。顺序反了，同一个元素可能被用两次。

1.2二分：每一步砍掉一半 A

在一本排好序的字典里找词，你不会从第一页翻。二分的动作是：看中间，比目标大就去左半边，小就去右半边。

binary_search.py
def binary_search(numbers, target):             # 输入排好序的数字、要找的值
    low, high = 0, len(numbers) - 1             # 搜索范围：最左、最右下标
    while low <= high:                          # 范围里还有数
        middle = (low + high) // 2              # 取中间下标
        if numbers[middle] == target:           # 正好是目标
            return middle                       # 交回下标
        if numbers[middle] < target:            # 目标在右半边
            low = middle + 1                    # 左边界右移
        else:                                   # 目标在左半边
            high = middle - 1                   # 右边界左移
    return None                                 # 没找到

[1, 3, 5, 7] 找 5：

轮次lowhighmiddlenumbers[middle]判断
103133 < 5，去右半边
22325相等，返回 2
真实踩过的坑。把 < 写成 <<（位移运算符），程序不报错，却永远返回 None。这类错误的特征是“语法合法、结果不对”，只能靠测试抓。

1.3链表、栈、队列：三种取法 C

看结论就过，知道什么时候用、从哪头取，够了。

结构取法典型场景
链表顺着 next 一个个走，不能按下标跳频繁在中间插入、删除
栈后进先出，pop() 从尾部取撤销、括号匹配、函数调用
队列先进先出，pop(0) 从头部取打印任务、消息排队

一句话区分：栈是“最后放的最先拿”，队列是“最先放的最先拿”。链表的重点不是取，而是“改箭头”：反转链表时，先把下一站存好，再改 current.next，否则链子会断。

进程与线程：四个工人同时数数

学完能做出：用四个线程安全地把计数加到 400；用队列把任务分给工人；知道超时和异常怎么处理。

你有 400 张图要缩，雇了 4 个工人，每人做 100 张。听起来只是“快四倍”，实际要先解决一件事：四个人往同一个本子上记数，容易互相覆盖。

2.1四个工人和一个计数器 A

目标是 400。先看正确的写法，再解释为什么需要锁。

thread_queue.py
import threading                              # 线程工具箱

def count_safely(repeats, workers):            # 每线程加几次、开几个线程
    state = {"count": 0}                        # 公共账本，所有线程共用
    lock = threading.Lock()                     # 一支笔：谁拿到谁才能改账本

    def worker():                               # 每个线程要做的事
        for _ in range(repeats):                # 重复指定次数
            with lock:                          # 进入时拿锁，离开时自动还
                state["count"] += 1             # 账本加一

    threads = []                                # 存线程的列表
    for _ in range(workers):                    # 按数量创建
        thread = threading.Thread(target=worker)  # 创建一个执行 worker 的线程
        threads.append(thread)                  # 放进列表
    for thread in threads:                      # 逐个发令
        thread.start()                          # 四个一起开工
    for thread in threads:                      # 逐个等收工
        thread.join()                           # 等四个都收工
    return state["count"]                       # 交回最终计数

三件事要能对着代码指出来：

  • state 是字典不是普通变量。普通变量在内层函数里赋值会变成“局部副本”，改不到外面。
  • start() 是发令枪，立刻返回；join() 是等收工。两个循环分开写，才是“同时开工”。
  • with lock 把“读—加一—写回”三步包成一段，一次只放一个工人进来。

2.2不加锁会怎样：1 而不是 2 B

普通 += 1 太快，两个线程不一定撞上。用 Barrier 强制“两人都先读完，再一起写”，这个 bug 就每次必现。

thread_queue.py
def demonstrate_lost_update():                  # 演示：两人同时加一，结果只加了一次
    state = {"count": 0}                        # 公共账本，初始 0
    both_read = threading.Barrier(2)            # 两人到齐才放行

    def worker():                               # 每个线程要做的事
        old_value = state["count"]              # 两人都读到 0
        both_read.wait()                        # 等另一个也读完
        state["count"] = old_value + 1          # 两人都写 1

    first = threading.Thread(target=worker)     # 第一个工人
    second = threading.Thread(target=worker)    # 第二个工人
    first.start()                               # 两个都发令
    second.start()                              # 两个都开跑
    first.join()                                # 等第一个收工
    second.join()                               # 等第二个收工
    return state["count"]                       # 结果是 1
时刻工人 A工人 B本子
1读到 0—0
2在 barrier 等读到 00
3写 0+1放行1
4—写 0+1（用它自己记的 0）1

测试写 == 1，不是因为它正确，而是因为它证明 bug 被稳定复现。正确结果本该是 2。

别把 both_read.wait() 放进锁里。A 拿着锁等人到齐，B 又进不来拿锁，两边永久卡住。

2.3用队列交任务 A

与其让多个线程抢同一堆变量，不如让他们从队列里取任务。队列自己管顺序。

thread_queue.py
import queue                                   # 线程安全队列

def process_tasks(tasks):                      # 接收一批任务
    jobs = queue.Queue()                        # 任务队列
    results = []                                # 处理结果
    for task in tasks:                          # 逐个准备任务
        jobs.put(task)                          # 放到队尾
    jobs.put(None)                              # 收工信号

    def worker():                               # 工人
        while True:                             # 一直取，直到收到停止信号
            task = jobs.get()                   # 从队头取一个
            if task is None:                    # 收到 None
                jobs.task_done()                # 告诉队列这个处理完了
                break                           # 退出循环
            results.append(task.upper())        # 注意缩进：在 if 之后
            jobs.task_done()                    # 标记当前任务完成

    thread = threading.Thread(target=worker)    # 建工人线程
    thread.start()                              # 开工
    jobs.join()                                 # 等队列清空
    thread.join()                               # 等工人退出
    return results                              # 交回结果

2.4停止、超时、异常 B

工人不能永远等，坏任务也不能让队列静默死掉。

thread_queue.py
def process_tasks_with_status(tasks):          # 带状态的任务处理
    jobs = queue.Queue()                        # 任务队列
    results = []                                # 结果列表
    for task in tasks:                          # 逐个入队
        jobs.put(task)                          # 入队
    jobs.put(None)                              # 收工信号

    def worker():                               # 工人要做的事
        while True:                             # 一直取到收工信号
            task = jobs.get()                   # 取任务
            if task is None:                    # 收工
                jobs.task_done()                # 告诉队列这条处理完了
                break                           # 退出循环
            try:                                # try 放在工人内部
                if task == "boom":              # 故意制造坏任务
                    raise ValueError("bad task")  # 抛出异常，模拟坏任务
                results.append({"task": task, "status": "ok", "result": task.upper()})  # 成功记录
            except Exception as error:          # 坏任务抛出的异常
                results.append({"task": task, "status": "error", "reason": str(error)})  # 失败也记录
            jobs.task_done()                    # 标记完成

    thread = threading.Thread(target=worker)    # 建工人线程
    thread.start()                              # 开工
    jobs.join()                                 # 等全部处理完
    thread.join()                               # 等工人退出
    return results                              # 交回带状态的结果

["a", "boom"] 的预期结果有两条：第一条 ok / A，第二条 error / bad task。跑出来对照，不要只看有没有报错。

超时那条：join(timeout=0.1) 只决定等多久，不会杀死线程。is_alive() 返回 True 说明它还在跑，之后要用 release.set() 让它自己走到终点。

def report(path):                               # 给路径，交回报告
    file_path = Path(path)                      # 包装成 Path 对象
    text = file_path.read_text(encoding="utf-8")  # 按 UTF-8 读文字

3.2逐行读：大文件不塞进内存 B

read_text() 把整份文件变成一个字符串。文件几 GB 时这会吃掉大量内存。逐行读每次只拿一行。

file_report.py
def count_file_lines(path):                     # 逐行统计
    total = 0                                   # 总行数
    nonempty = 0                                # 非空行数
    with Path(path).open(encoding="utf-8") as file:  # 打开文件，离开 with 自动关
        for line in file:                       # 每次只读一行
            total += 1                           # 总行数加一
            if line.strip():                     # 去掉空白后还有内容
                nonempty += 1                    # 非空行加一
    return total, nonempty                       # 一起交回两个数

3.3三种错误，三个状态 A

缺失文件、空文件、编码不对，是三件事。把它们混成一个“读取失败”，后面排查就没法定位。

file_report.py
def safe_report(path):                          # 三种情况分开报
    file_path = Path(path)                      # 路径对象
    if not file_path.exists():                  # 文件不存在
        return {"status": "missing", "path": str(file_path)}  # 报缺失
    try:                                        # 试着读，编码不对就跳出去
        total, nonempty = count_file_lines(file_path)  # 试着逐行读
    except UnicodeDecodeError:                  # 编码不对，读不出来
        return {"status": "decode_error", "path": str(file_path)}  # 如实报编码错误
    return {"status": "ok", "lines": total, "nonempty": nonempty}  # 正常结果
输入返回说明
不存在的路径{"status":"missing"}先查存在，不打开
0 字节的文件{"status":"ok","lines":0,"nonempty":0}空是正常输入，不是错误
GBK 编码的文件{"status":"decode_error"}读不出来要如实报

3.4路径与编码：两条结论 C

一，用 Path(__file__).parent / "sandbox" / "sample.txt" 拼路径，不管你从哪个目录启动，都指向同一份文件。用 Path("sandbox/sample.txt") 就跟着“当前目录”跑，换个目录就找不到。

二，读写文本永远写死 encoding="utf-8"。中文一个字符占 3 字节，所以字节数和字符数不相等：你好 是 6 字节、2 字符。Windows 默认编码可能是 GBK，不写死就会乱码或报 UnicodeDecodeError。

import socket                                  # TCP 工具箱

def echo_once(connection):                     # 处理一个连接
    while True:                                # 持续收发
        data = connection.recv(1024)            # 最多收 1024 字节
        if not data:                            # 空 bytes：对方关了发送
            break                               # 结束循环
        connection.sendall(data)                # 原样发回去

def serve_once(host="127.0.0.1", port=18080):  # 只接待一个客户端
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:  # IPv4 TCP socket
        server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)   # 重跑可复用端口
        server.bind((host, port))               # 绑定地址和端口
        server.listen(1)                        # 开始监听
        print("listening", host, port)          # 提示已就绪
        connection, address = server.accept()   # 等到有人打进来
        print("connected", address)             # 显示对方地址
        with connection:                        # 用完关闭
            echo_once(connection)               # 收到什么回什么

if __name__ == "__main__":                      # 直接运行才启动
    serve_once()                                # 开始接待

4.3HTTP 只是套了格式的 TCP B

TCP 只管把字节送到，不管这些字节是什么意思。HTTP 规定这些字节怎么排：请求行、头部、空行、正文；响应里还要有状态码。

本机 HTTP 演示
from http.server import BaseHTTPRequestHandler, HTTPServer  # 请求基类、服务器
import threading, urllib.request                 # 线程、HTTP 客户端

class Handler(BaseHTTPRequestHandler):            # 处理请求
    def do_GET(self):                             # 只接 GET
        self.send_response(200)                   # 状态码 200
        self.send_header("Content-Type", "text/plain; charset=utf-8")  # 响应类型
        self.end_headers()                        # 头结束
        self.wfile.write("pong".encode("utf-8"))  # 写响应体
    def log_message(self, *args):                 # 覆盖访问日志
        pass                                       # 不打印访问日志

server = HTTPServer(("127.0.0.1", 18082), Handler)  # 绑定本机端口
threading.Thread(target=server.serve_forever, daemon=True).start()  # 后台运行

with urllib.request.urlopen("http://127.0.0.1:18082/", timeout=3) as response:  # 发 GET
    print("状态码：", response.status)             # 打印状态码
    print("响应体：", response.read().decode("utf-8"))  # 打印正文

server.shutdown()                                 # 关掉服务
实际输出
状态码： 200
响应体： pong

urllib 替你做了三件事：建 TCP 连接、按 HTTP 格式写请求、按 HTTP 格式解析响应。它没有换掉 TCP，只是在 TCP 上按约定说话。

SQLite：把数据留住

5.1建表、加一条、读回来 B

todo_db.py
import sqlite3                                  # 自带数据库

def create_table(connection):                   # 建表
    connection.execute("CREATE TABLE IF NOT EXISTS tasks (id INTEGER PRIMARY KEY, text TEXT, done INTEGER)")  # 三列：编号、内容、是否完成

def add_task(connection, text):                 # 添加一条
    cursor = connection.execute("INSERT INTO tasks(text, done) VALUES (?, ?)", (text, 0))  # 问号占位
    connection.commit()                         # 提交，否则不保存
    return cursor.lastrowid                     # 返回数据库分配的编号

def list_tasks(connection):                     # 查询全部
    cursor = connection.execute("SELECT id, text, done FROM tasks ORDER BY id")  # 按编号排序
    return cursor.fetchall()                    # 取出所有行

SQL 每个词是什么意思

SQL 不是魔法咒语，它是一句有固定语序的指令。把上面出现的语句拆开看：

片段读法作用
CREATE TABLE IF NOT EXISTS tasks建表；已有同名表就跳过表是数据的一层“容器”，先有表才能插行
(id INTEGER PRIMARY KEY, text TEXT, done INTEGER)括号里三列：整数主键、文本、整数列名、类型、约束，用逗号隔开
INSERT INTO tasks(text, done)往 tasks 表的这两列插入没写的列用默认值（id 自动递增）
VALUES (?, ?)两个值先用问号占位真实值由 execute 的第二个参数按顺序填
SELECT id, text, done我要这三列列的书写顺序 = 返回元组的顺序
FROM tasks ORDER BY id从 tasks 表，按 id 升序不加 ORDER BY，顺序由数据库自己决定
UPDATE tasks SET done = 1把 done 这一列改成 1只改你指定的列
WHERE id = ?只对 id 等于这个值的行动手省略 WHERE 就是改整张表
DELETE FROM tasks WHERE id = ?删掉 id 等于这个值的那行省略 WHERE 就是清空整张表
CREATE INDEX ... ON tasks(text)给 tasks 的 text 列建一份“目录”只影响查找快慢，不改任何一行数据

connection.execute(...) 交回一个 cursor（光标），你从它身上取三样东西：

取法拿到什么用在哪
cursor.fetchall()查询结果的全部行，每行是一个元组读数据
cursor.lastrowid刚插入那行的 id插入后要知道新编号
cursor.rowcount这次改/删了几行（可能是 0）判断“有没有真的动到数据”

with connection: 是事务开关：块里全部成功就提交，中途抛异常就回滚。

flowchart TD
    S["事务开始"] --> A["INSERT A 成功"]
    A --> B["INSERT B 写错列"]
    B --> C{"整组成功？"}
    C -->|"是"| D["commit：两条都在"]
    C -->|"抛异常"| E["rollback：A 也撤销"]

看图要点：两条插入是同一组，没有“只成功一条”的出口。

Chapter 6

日志诊断：用证据回答“为什么失败”

学完能做出：读一份离线日志，回答请求有没有到达、哪一步失败、耗时多少、能不能重试。

“请求好像卡了”不是结论。拿证据要回答四件事：开始了没有、在哪结束、失败原因、耗时多少。这一章用一份离线日志，不发请求。

6.1把一行文字变成可查询的结构 B

sandbox/events.log 每行是 时间 request_id 级别 事件，共四行：

日志原文
0.0 r1 INFO start
1.25 r1 ERROR timeout
1.5 r2 INFO start
2.0 r2 INFO finish

解析要做的事：切四段、时间转数字、装进字典。切不出四段或时间不是数字的行，计入 bad_lines，不能静默丢掉。

diagnose_request.py
from pathlib import Path                          # 处理文件路径

def load_events(path):                            # 输入日志文件路径
    events = []                                   # 装解析好的事件
    bad_lines = 0                                 # 数坏行，不能悄悄丢掉
    for line in Path(path).read_text(encoding="utf-8").splitlines():   # 一次读全文，按行切开
        parts = line.split(maxsplit=3)            # 按空白切四段：时间、编号、级别、事件
        if len(parts) != 4:                       # 不够四段 = 这行不合法
            bad_lines += 1                        # 记一笔坏行
            continue                              # 跳过，继续下一行
        try:                                      # 试着把时间转成数字
            events.append({"time": float(parts[0]), "request_id": parts[1],   # 时间转小数，编号原样
                           "level": parts[2], "event": parts[3]})              # 级别、事件名原样
        except ValueError:                        # 时间不是数字
            bad_lines += 1                        # 也算坏行
    return events, bad_lines                      # 交回事件列表和坏行数

6.2失败要分类，还要说能不能重试 A

同样叫“失败”，处理方式不一样：超时可以再试，404 再试还是 404。

错误含义retryable
timeout等太久没回应True
connection_refused对方端口没开True
http_404地址不存在False
http_500服务端内部错误True
没见过的事件名没有依据None
diagnose_request.py
RETRYABLE = {"timeout", "connection_refused"}     # 重试有用的错误名
NOT_RETRYABLE = {"http_404", "json_parse"}        # 重试也没用的错误名

def classify(error_event):                        # 输入一条 ERROR 事件
    name = error_event["event"]                   # 事件名就是错误原因
    if name.startswith("http_"):                  # 形如 http_404 / http_500
        code = int(name.split("_")[1])            # 从名字里取出状态码
        retryable = code >= 500 or code == 408   # 5xx 或 408 值得重试
    elif name in RETRYABLE:                       # 白名单：超时、拒连
        retryable = True                          # 可以重试
    elif name in NOT_RETRYABLE or name.startswith("json"):   # 404、解析失败这类
        retryable = False                         # 重试无意义
    else:                                         # 没见过的事件名
        retryable = None                          # 不下结论，留空
    return {"reason": name, "retryable": retryable}   # 原因 + 能不能重试

三态必须分清，比较时用 is True / is False，不能用 == 糊过去。

6.3诊断与汇总 B

对每个 request_id：先筛出它的事件，按时间排序；有 ERROR 就是失败，否则必须同时有 start 和 finish 才能算耗时，缺一个就返回 unknown。

diagnose_request.py
def diagnose(events, request_id):                 # 输入全部事件、要查的编号
    selected = [e for e in events if e["request_id"] == request_id]   # 只留这个请求的事件
    if not selected:                              # 一条都没找到
        return {"status": "unknown", "reason": "request not found"}   # 没到达，或没有记录
    selected.sort(key=lambda e: e["time"])        # 按时间从早到晚排
    errors = [e for e in selected if e["level"] == "ERROR"]   # 挑出所有 ERROR
    if errors:                                    # 有错误就判失败
        info = classify(errors[0])                # 拿第一条错误做分类
        return {"status": "failed", "reason": info["reason"], "retryable": info["retryable"]}   # 失败 + 原因 + 能否重试
    starts = [e for e in selected if e["event"] == "start"]   # 找开始事件
    finishes = [e for e in selected if e["event"] == "finish"]   # 找结束事件
    if not starts or not finishes:                # 缺头或缺尾
        return {"status": "unknown", "reason": "incomplete trace"}   # 证据不全，不算成功
    return {"status": "ok", "duration": round(finishes[-1]["time"] - starts[0]["time"], 3)}   # 成功：最后一次结束减第一次开始
样例诊断结果
r1: 失败于 timeout，可重试
r2: 成功，耗时 0.5 秒

0.5 来自 2.0 - 1.5，不是估的。所有请求汇总时，先把编号去重（{event["request_id"] for event in events}），再排序，输出顺序才稳定。

6.4坏行必须计数 C

拿三行坏日志试：一行正常、一行字段数不对、一行时间不是数字。正确结果是“解析成功 1 条、坏行 2 条”。跳过坏行而不计数，你会在“少了几条记录”时毫无察觉。
